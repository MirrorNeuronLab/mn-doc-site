Start with the [blueprint package format](./blueprint-standard.mdx). Put logical dependencies in `workflow.json`, worker configuration in `execution.json`, and package versions in `dependencies.json`.

## Select Python step handlers

In a compiled blueprint, a step can name a Python module. The default step runtime calls the module's `run()` function. The dependency in this example runs intake before review.

```json
{
  "$schema": "https://mirrorneuron.io/schemas/blueprint/v1/workflow.schema.json",
  "steps": [
    {"id": "intake", "needs": [], "run": {"handler": "my_blueprint.steps.intake"}},
    {"id": "review", "needs": ["intake"], "run": {"handler": "my_blueprint.steps.review"}}
  ]
}
```

This example is a workflow document. Pair it with an execution document that selects a worker and a package that makes both modules importable. Choose a compatible runner and set the worker image or worker binding for the package.

## Add reusable dependencies

Declare a skill or agent using its distribution name and version. Include the SDK components your code uses as `packages` records in `dependencies.json`. See [Dependency versions](./blueprint-standard.mdx#dependency-versions). Use `mn.blocks` to bind reusable blueprint blocks to logical steps when you can use a block's declared inputs and outputs.

For an editable source install, `MN_USE_LOCAL_SKILLS=1` resolves matching local projects in the workspace or packaged source trees. Binary preparation resolves available releases that satisfy the constraints. Review any on-install hooks as executable code.

## Check dependencies before launch

Run the checks from the blueprint's parent directory.

```bash
mn blueprint validate ./my-blueprint
mn blueprint doctor ./my-blueprint --check-only
```

Fix missing imports, packages, images, and service requirements. For a live smoke test, use the blueprint's documented sample configuration and review access to files, credentials, and external services. See [Run your first blueprint](./quickstart.mdx) and [Prepare files and services for Docker and OpenShell](./docker_and_openshell_for_blueprints.mdx).
