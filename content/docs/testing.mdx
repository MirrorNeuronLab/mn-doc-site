## Check your blueprint

Attach to a local runtime and check the reviewed package from its parent directory.

```bash
mn blueprint validate ./my-blueprint
mn blueprint doctor ./my-blueprint --check-only
```

Fix the reported configuration and dependency issues. For a live test, use approved sample data and review the blueprint's actions before launch. Compare the [run outputs and events](./monitor.mdx) with the result you expected.

## Common commands

The source workspace's `mn-system-tests` repository provides the `mn_test` runner. Set up its environment with Python 3.12 or newer from the test repository.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/mn_test --list
```

Select the suite that covers your change. Preview prerequisites with `--dry-run`.

| Check | Command |
| --- | --- |
| API, CLI, and SDK contract checks | `.venv/bin/mn_test --suite contracts` |
| API unit tests | `.venv/bin/mn_test --component mn-api --level unit` |
| Installer checks | `.venv/bin/mn_test --suite installer` |
| Local catalog validation | `.venv/bin/mn_test --suite blueprints.local --blueprints-local "<catalog-dir>" --offline` |

Replace `<catalog-dir>` with a local catalog containing `index.json`. A normal development run can refresh local editable packages. Use `--skip-python-refresh` when you have already prepared the environment.

## Manual live end-to-end checks

Some suites start disposable services and execute test payloads. Preview the suite selection, prerequisites, and capability gates first.

```bash
.venv/bin/mn_test --suite mn-system-tests.integration --suite mn-system-tests.e2e --dry-run
```

Remove `--dry-run` when the required tools and test inputs are ready. Use separate storage, credentials, and ports for live tests. The runner's reports under `results/runs/<run-id>/` include suite status, logs, and cleanup diagnostics. Check skipped and blocked suites before relying on the result.

See [System benchmarks](./system-benchmarks.mdx) for performance and context measurements.
