---
title: "Write for the user guide"
description: "Write procedures and references that readers can follow on their own installations."
---

## Start with the reader's task

Give each page a specific outcome. Put prerequisites and the first action near the top. Use short, direct language and the names readers see in the UI or CLI. Define a new term at first use, then link to [Blueprints, jobs, and runs](./core-concepts.mdx) when the identifiers matter.

## Make procedures usable

Show where to run each command and how to fill in placeholders. Tell the reader what to check before moving on. For a change to data or services, explain the effect before the command and describe how to verify or recover. Use reviewed sample inputs. Keep credentials out of examples and command output.

## Keep references current

Check command syntax against the CLI registry or help and HTTP shapes against OpenAPI and route handlers. Check blueprint settings against the packaged schemas and runtime defaults against their owning configuration. Put detailed background in the relevant component docs and link from the user guide where the reader needs it.

## Verify the page

Run the site type check and build. Open the affected page and check its links, heading anchors, and code examples. Preserve existing page URLs when reorganizing navigation. See [Contribute to MirrorNeuron](./contributing.mdx#improve-this-guide) for the preview commands.
