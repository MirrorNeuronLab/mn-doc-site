---
title: "Use the Python SDK"
description: "Read jobs from Python, launch a local bundle, or compile a blueprint for validation."
---

Use Python 3.12 or newer and an SDK release compatible with your runtime. Use the installed environment if it already provides the SDK. For a separate Python environment, install `mirrorneuron-python-sdk[client]` from your MirrorNeuron package source. See [HTTP API](./api.mdx) for an HTTP integration.

## Inspect jobs and runs

Run this from the environment of a [connected installation](./installation.mdx). `RuntimeResources` uses its saved connection. Keep the connection file and credentials private.

```python
from mn_sdk.runtime_resources import RuntimeResources

runtime = RuntimeResources()
jobs = runtime.request("GET", "/jobs")
for job in jobs["items"]:
    print(job)
```

Pass the returned `next_page_token` as `page_token` to read the next page. For a known run, use `runtime.request("GET", "/runs/" + resource_id(run_id))` with `resource_id` imported from `mn_sdk.runtime_resources`.

## Launch a local bundle from Python

On the runtime host, with direct Core connection settings available to the SDK, run this from the parent of a reviewed bundle directory. Launch prepares a job and starts execution. Use sample inputs and review worker actions first.

```python
from mn_sdk.public import MirrorNeuron

with MirrorNeuron() as runtime:
    run = runtime.launch("./my-blueprint")
    print(run.job_id, run.run_id)
    print(run.status())
```

Use `run.events()` to follow events or `run.wait(timeout=60)` to wait for a terminal state. A wait timeout leaves work running. Retain the IDs to look up the execution. Use `start(job_id)` for a later run of the saved job. Async applications can use `AsyncMirrorNeuron`.

Direct SDK clients read `MN_GRPC_TARGET`, `MN_GRPC_TIMEOUT_SECONDS`, and `MN_GRPC_AUTH_TOKEN` or the corresponding runtime configuration. If you use `mn_sdk.Client` directly, `list_runs(job_id)` takes a job ID and returns a JSON string. See [Configuration](./env_variables.mdx).

## Load and compile a blueprint

Replace `./my-blueprint` with a reviewed folder or ZIP. Compilation can import declared StepSpec code.

```python
from mn_sdk.blueprints import compile_blueprint, open_blueprint, resolve_config

with open_blueprint("./my-blueprint") as package:
    configuration = resolve_config(package, {})
    compiled = compile_blueprint(package, configuration)
    print(package.manifest["id"], compiled.fingerprint)
```

The compiler returns a descriptor and fingerprint. To prepare resources and execute the compiled workflow, use the launch path above or [Run your first blueprint](./quickstart.mdx).

## Declare optional capabilities

Declare SDK components under `packages` in `dependencies.json`. Install only the capabilities your workers use. For example, add `mn-python-sdk-mcp` for an MCP integration or `mn-python-sdk-rag` with the `milvus` extra when your blueprint uses Milvus. Select versions compatible with your SDK and runtime. See [Dependency versions](./blueprint-standard.mdx#dependency-versions).

Within a prepared worker, `ComponentRegistry.from_environment()` reads the component declarations. Resolve an MCP tool service with `registry.service("mcp", "call_tool")` when the package declares that capability. Lookup uses prepared dependencies.
