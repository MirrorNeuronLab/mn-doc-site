Use these guides to configure how the runtime starts and supervises your work.

| Task | Guide |
| --- | --- |
| Choose an owner and connect peers | [Connect runtime nodes](./cluster.mdx) |
| Reserve CPU, memory, disk, or a GPU | [Resources and devices](./resources-and-devices.mdx) |
| Start at a specific time or wait for capacity | [Schedules and events](./schedules-and-events.mdx) |
| Discover a service and check that it is ready | [Services and health checks](./services-and-health-checks.mdx) |
| Maintain a node or move a stopped job | [Node maintenance](./cluster.mdx#drain-a-node-for-maintenance) · [Moving an idle job](./cluster.mdx#moving-an-idle-job) |
| Recover a failed or interrupted run | [Reliability and recovery](./reliability.mdx) |
| Prepare a new version of a service | [Update a long-running job](./deployments.mdx) |

The owner admits work against its own capacity, records state in its writable Redis store, and dispatches workers through the blueprint's runner. See [Execution behavior](./runtime-architecture.mdx) for the relationship between the surface, owner, and worker.
