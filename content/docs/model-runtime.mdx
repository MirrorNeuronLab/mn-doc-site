---
title: "Configure and diagnose models"
description: "Install the model a blueprint needs or connect an OpenAI-compatible provider."
---

Review the blueprint's model requirements first. A workflow can use a managed local model, an OpenAI-compatible provider, or no model at all. Run model commands from a CLI attached to your runtime.

## Find and prepare a model

```bash
mn model list --available
mn model add <model-id>
mn model doctor <model-id>
```

Replace `<model-id>` with the required catalog ID or a reviewed Docker Model Runner reference. The catalog can also contain NVIDIA Docker models. Adding a local model can download weights and prepare the managed LiteLLM route. Use `--node <node>` to select a runtime node, or `--local` to use the entry runtime. Fix hardware or backend errors before launching.

Use `mn model add --default` to prepare the first compatible configured default. To give one reviewed reference priority, use `mn model add <model-id> --default`. The priority persists until changed or removed. Use `mn model show` to inspect the default and fallbacks.

## Register an OpenAI-compatible provider

Save a definition like this as `provider-models.json` **on the entry runtime**. Replace the endpoint and model values with the ones your provider supports.

```json
{
  "provider": {
    "openai-compatible": {
      "options": {
        "baseURL": "https://models.example.com/v1",
        "apiKeyEnv": "MODEL_PROVIDER_API_KEY"
      },
      "models": {
        "my-provider-model": {
          "name": "My provider model",
          "model": "provider-model-name",
          "timeout_seconds": 120
        }
      }
    }
  }
}
```

Set the referenced `MODEL_PROVIDER_API_KEY` in the native runtime service's environment. Keep the value out of the definition. Requests can send prompts and other inputs to that provider and incur charges.

Register the provider from the attached CLI. Use the file's absolute path on the runtime.

```bash
mn model add --file /path/to/provider-models.json
mn model show my-provider-model
mn model doctor my-provider-model
```

The runtime checks the file and credentials before changing the registry. Use `mn model update <model-id>` to reload the saved provider file. A file passed with `--default` must define exactly one model.

## Verify model capabilities

Wait for the model and gateway to become ready, then probe the capabilities the blueprint needs. Probes send live model requests.

```bash
mn model probe <model-id> --capabilities image,json-schema,stream
```

The probe writes the observed matrix to the runtime's `$MN_HOME/models/catalog.json`. A verified `false` means the feature is unsupported. Unknown results or request failures need investigation. An entry-node Docker Model Runner model also gets a direct check for parity with the gateway. Provider and remote routes are checked through LiteLLM.

## Configure the blueprint

Set the registered model ID in the blueprint's model configuration. See [Author a blueprint](./blueprint-standard.mdx#extensions) for the `mn.llm` extension. From the parent of a reviewed local package, run `mn blueprint doctor ./my-blueprint` and resolve any route or capability errors.

## Run admission and model residency

A run uses its job owner's reservation for managed inference, embeddings, and local fallback. A model listed on another node is only a catalog or routing observation. For a run that needs that model, choose a compatible owner before creating the job. Hosted providers remain accessible through configured gateway routes.

Pausing can keep the managed model resident. After the final run reference closes and its requests drain, the runtime unloads the weights from memory and retains installed artifacts. Pending cleanup can hold capacity. See [Resources and devices](./resources-and-devices.mdx).

## Remove a model

Preview with `mn model remove <model-id> --dry-run`. Check for dependent jobs and retain the provider file or model artifacts you need. Confirm removal with `mn model remove <model-id> --yes`. Use `--keep-artifact` when you want to keep an installed artifact while removing its registration.
