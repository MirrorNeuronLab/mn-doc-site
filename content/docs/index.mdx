MirrorNeuron runs packaged workflows called **blueprints**. Create a durable **job**, start a **run**, and inspect its logs and outputs with the CLI or HTTP API.

## Start here

1. [Install MirrorNeuron](installation.mdx) and check runtime health.
2. [Run your first blueprint](quickstart.mdx) using reviewed sample inputs.
3. [Monitor the run](monitor.mdx), collect outputs, and handle human requests.

## Know these three terms

A blueprint is the reusable package. A job stores its configured definition. A run is one execution of that job. Use the job ID to start another execution, and the run ID to inspect, pause, resume, or cancel it. See [Core concepts](core-concepts.mdx).

Begin with sample data and review each blueprint's worker code, model endpoints, and external actions before running it. A completed run still requires review of its outputs.
