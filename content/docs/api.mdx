## Connect and authenticate

Run the API on a [combined or client installation](./installation.mdx) with a saved runtime connection. The default base URL is `http://localhost:54001/api/v1`. Set the base URL in your shell and check the API process.

```bash
MN_API_BASE=http://localhost:54001/api/v1
curl --fail-with-body -sS "$MN_API_BASE/health"
```

Check that `api_contract` is `mirrorneuron.rest.v1`. The health response also reports whether API authentication is enabled. Set `SURFACE_API_TOKEN` privately to the API's `MN_API_TOKEN` or the token in its installation's `api.token` file. The runtime control token is used separately to attach the surface. Call `GET /runtime/health` to check the connected runtime. For the full schema, open `/api/v1/openapi.json` on your API host.

## Upload a package and create a job

Review the bundle code and external actions before uploading. Send `worker-bundle.zip` as a multipart file from the directory containing it.

```bash
curl --fail-with-body -sS "$MN_API_BASE/bundles" \
  -H "Authorization: Bearer $SURFACE_API_TOKEN" \
  -F "bundle=@./worker-bundle.zip"
```

Replace `<bundle-id>` with the returned ID and `<create-key>` with a unique key for this request. Use `blueprint_id` in place of `bundle_id` to create a catalog job. Use `resolved_configuration` when supplying saved job settings.

```bash
curl --fail-with-body -i "$MN_API_BASE/jobs" \
  -H "Authorization: Bearer $SURFACE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: <create-key>" \
  -d '{"bundle_id":"<bundle-id>"}'
```

Save the job ID and ETag. Creating a job can prepare the package's declared resources. Start a run separately when you are ready to execute it.

## Start and inspect a run

Replace `<job-id>` with the job ID and `<start-key>` with a new key for this execution. Supply the job's expected `inputs`.

```bash
curl --fail-with-body -i "$MN_API_BASE/jobs/<job-id>/runs" \
  -H "Authorization: Bearer $SURFACE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: <start-key>" \
  -d '{"inputs":{}}'
```

`202 Accepted` returns a run receipt. Use its public `run_id` at `GET /runs/{run_id}`. A catalog job can also accept `config_overrides`. Changes to resolved settings can reprepare the saved definition before execution.

### Queue work when the owner is busy

Use `POST /jobs/{job_id}/run-admission-checks` with `{"action":"start"}` to read a snapshot of the owner's capacity. The owner checks capacity again at start. A start with default `admission_policy: "start_now"` rejects a busy owner. To accept a wait, send `"admission_policy":"enqueue_if_busy"` in the start request. Keep the returned ID and inspect its `admission` and `placement` fields if the status is `queued`. The owner starts compatible work when capacity allows.

## Pause, resume, or cancel

```bash
curl --fail-with-body -sS -X PATCH "$MN_API_BASE/runs/<run-id>" \
  -H "Authorization: Bearer $SURFACE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"desired_state":"paused"}'
```

Use `running` to resume or `cancelled` to cancel. Send `{"desired_state":"cancelled","queued_only":true}` to cancel an unstarted run only. Invalid transitions return `409`. If work has already performed external actions, handle those actions in the external system.

### Checkpoint retry

To retry an eligible failure, first `POST /runs/{run_id}/retry-plans` with `{"configuration_overrides":{}}`. Send the plan's `expected_attempt` and `checkpoint_revision` in `POST /runs/{run_id}/retries` along with the required `Idempotency-Key`. A retry retains the run ID. See [Manual checkpoint retry](./reliability.mdx#manual-checkpoint-retry).

## Follow progress and retrieve outputs

```bash
curl --fail-with-body -sS -N "$MN_API_BASE/runs/<run-id>/events/stream" \
  -H "Authorization: Bearer $SURFACE_API_TOKEN"
```

Persist the last applied event ID and send it in `Last-Event-ID` on reconnect. A stream closes after a terminal event. Read the current run and its event history to reconcile gaps. Use `GET /runs/{run_id}/outputs` or `GET /runs/{run_id}/artifacts` and follow the returned download URLs.

## Pagination and safe updates

- Collections return `items` and `next_page_token`. Use `page_size` from 1 to 200 (default 50). Pass the next token unchanged with the same filters. Tokens expire within 24 hours and can be lost on restart or eviction.
- Keep the same idempotency key and request body after an uncertain response. Check the existing run or operation before submitting fresh work. A conflicting reuse of a retained key returns `409`.
- Where an endpoint requires `If-Match`, send the ETag from the latest read. Missing conditions return `428` and stale conditions return `412`.
- Errors use `application/problem+json` with a `code`, `detail`, and `request_id`. Background failures appear on the accepted operation.

## Prepare a catalog blueprint

`POST /blueprints/{blueprint_id}/additions` with `{"force":false}` returns an operation. Follow its `Location` or `GET /operations/{operation_id}/events/stream` until it completes or fails. Preview removal with `POST /blueprints/{blueprint_id}/removals` and `{"dry_run":true}` before confirming a request that could delete owned resources.

## Job UI relay

Use `GET /jobs/{job_id}/ui` to read the current job UI descriptor. Forward HTTP to `/jobs/{job_id}/ui-proxy/{port}/{path}` and WebSocket connections to `/jobs/{job_id}/ui-proxy/{port}/ws/{path}`. The runtime checks the active execution and declared ports. The relay strips the surface credential before forwarding to the worker.

## Connect a job to an MCP client

Prepared jobs can expose supervision at `/api/v1/jobs/{job_id}/mcp` over Streamable HTTP. Use `get_capabilities` and `get_user_manual` to see the job's current tools and permissions. The supervision profile can read bounded status and results and can also start, pause, resume, or stop runs. Supply stable request IDs to tools that change state. Jobs with a response service may additionally offer `ask_job`.

Use the surface bearer credential for trusted direct access or a job-scoped OAuth connection for an external MCP client. See [Execution and data access](./security.mdx#secrets-and-data-movement) before enabling access.
