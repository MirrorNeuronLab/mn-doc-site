MirrorNeuron runs packaged, message-driven workflows on machines you operate. Use it to run a reviewed workflow repeatedly, inspect the evidence from each execution, or connect workflow results to another application.

## Evaluate a workflow

| If you need to… | Try this |
| --- | --- |
| Repeat a workflow with saved configuration or shared data | Read [Blueprints, jobs, and runs](./core-concepts.mdx) and create a durable job. |
| Run on a machine with a model, GPU, or required service | Check the blueprint's [model requirements](./model-runtime.mdx) and [resource profile](./resources-and-devices.mdx). |
| Review failures or approval requests | Use the Web UI or [monitor the run](./monitor.mdx) through the CLI. |
| Connect an application | Use the [HTTP API](./api.mdx) or [Python SDK](./sdk.mdx). |
| Operate several machines | Review [node ownership and federation](./cluster.mdx) before connecting them. |

## Review the boundaries

Each job has an owning runtime. That owner controls execution and recovery. Retries can repeat worker actions, so use an idempotency strategy for writes or requests that have external effects.

Data follows the files, connectors, and model endpoints selected by the blueprint. Choose a runner and review the access it grants before processing sensitive inputs. Use workflow outputs with the review required for your use case. See [Execution and data access](./security.mdx).

To evaluate a workflow with sample data, [install MirrorNeuron](./installation.mdx) and [run a blueprint](./quickstart.mdx).
