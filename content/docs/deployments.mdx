---
title: "Update a long-running job"
description: "Prepare a revised job definition and verify its next run."
---

Use the durable job definition to manage versioned configuration and bundles. Each execution has its own run ID. Plan a change window for a service if you need to stop or replace its attached run.

## Prepare the change

1. Record the job ID, current bundle or blueprint version, and the attached run ID.
2. Download outputs you need and back up persistent data before replacing a run or modifying the definition. See [Back up, restore, or move a job](./cli.mdx#back-up-restore-or-move-a-job).
3. Review the new package and use [blueprint validation](./blueprint-standard.mdx#validate-and-try-the-package) with sample inputs. Confirm model, service, and device requirements on the intended owner.

## Update the saved definition

Through the HTTP API, read `GET /api/v1/jobs/{job_id}` and keep its ETag. Use `PATCH /api/v1/jobs/{job_id}` for supported definition changes. To replace a bundle-backed definition's package, upload the new bundle and send its `bundle_id` in `PUT /api/v1/jobs/{job_id}/bundle`. Send the current ETag in `If-Match`. Read the resulting job and check its version and configuration before starting work. See [HTTP API](./api.mdx).

A new batch run uses the saved definition. A service has one attached run. To replace it, use the explicit [service replacement procedure](./cli.mdx#jobs-and-runs). That operation removes the old run's history and artifacts, so save them first.

## Verify and recover

Use the new run ID to check [state, logs, and service health](./monitor.mdx). If the update fails validation or the next run fails, review the error and use your retained bundle, configuration, or backup to recover. Restore a backup under a new job ID to inspect it before starting fresh work.

The public interfaces use jobs and runs for this procedure. The internal rollout controller's rolling, canary, and blue-green operations are available to Core integrations through Elixir. Use the [CLI](./cli.mdx) and [HTTP API](./api.mdx) for supported operator controls.
