---

Set up the test runner in [Validate a workflow or integration](./testing.mdx#common-commands). Run the examples from `mn-system-tests` with its prepared Python environment.

## Choose a workload

| Suite | What it measures |
| --- | --- |
| `benchmarks` | Workflow benchmark fixtures and report contracts |
| `performance` | API, SDK, and CLI interface timing and stream parsing |
| `performance.api` | API preparation and Chat response timing, including first answer content and completion |
| `membrane.job-io-context` | Retrieval from prepared job input and output folders, source coverage, and citation accuracy |

```bash
.venv/bin/mn_test --suite performance --dry-run
.venv/bin/mn_test --suite performance
```

The performance suite uses injected interfaces by default. Its live endpoint probes require explicit opt-in and prepared services. Check the selected suite's prerequisites before adding live endpoints or credentials. [Test runner usage](https://github.com/MirrorNeuronLab/mn-system-tests/blob/main/USAGE.md)

## Read the report

Open the fresh `results/runs/<run-id>/` directory. The interface suite writes `performance.txt` and `performance.json`. Compare the hardware, component revisions, fixture configuration, and skipped probes before comparing timings.

For context retrieval, check required evidence coverage, citation paths, and scope leaks alongside latency. Keep cold and warm queries separate. A context score measures the selected evidence on the test corpus. Review application outputs separately before drawing conclusions about answer quality.
