## Report a problem

Include what you tried, what you expected, and what happened. For a runtime issue, include the installed version, platform, installation role, and the relevant public IDs and timestamps. Add sanitized logs or a small reproduction. Keep credentials, customer data, and security details private. See [Troubleshooting](./troubleshooting.mdx).

## Verify a change

Use the [component map](./component-guide.mdx) to find the relevant repository and follow its development setup. Run a focused check from the component first. For cross-component contracts, use [the system test runner](./testing.mdx#common-commands).

If you need a runtime from editable sibling checkouts, run `./install.sh --mode local` from `mn-deploy` after reviewing its help and selecting a development home. Check service health before launching sample workflows. See [Install MirrorNeuron](./installation.mdx).

## Improve this guide

Update the steps or reference the reader needs. Use Node.js 22 or later to build and preview the site from `mn-doc-site`.

```bash
npm ci
npm run types:check
npm run build
npm run dev
```

Open [the local guide](http://localhost:3000/docs) and try the affected links and navigation. Record the command, schema, or test that confirms changed behavior when you submit the change. See [Writing for the user guide](./documentation-style.mdx).
