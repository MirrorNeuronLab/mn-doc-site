## Discover the active catalog

List the catalog from your CLI installation and use an ID from that list to read its details.

```bash
mn blueprint list
mn blueprint show <blueprint-id>
```

The list reads the CLI's configured catalog. Details and launch resolve on the connected runtime, which needs a matching entry. See [Catalog configuration](./env_variables.mdx#blueprint-catalog-resolution). Review the package README for sample inputs, available runners, and model, service, or device requirements. Check what files, credentials, and external services the workflow uses.

## Check a local package

Attach to a local runtime and run these checks from the package's parent directory.

```bash
mn blueprint validate ./my-blueprint
mn blueprint doctor ./my-blueprint --check-only
```

Replace `./my-blueprint` with the reviewed package's path. Fix blocking errors before launch. See [Run your first blueprint](./quickstart.mdx) for the full walkthrough.

## Launch a catalog blueprint

Use an ID from the connected runtime's catalog. For a remote runtime, supply any input paths as seen by that runtime. Starting the package can prepare dependencies and execute external actions, so start with approved sample inputs.

```bash
mn blueprint run <blueprint-id> --detached
```

When the Web UI is enabled, you can also open **Start a run**, choose a blueprint, review its configuration, and submit it. Use the run ID to [follow progress and collect outputs](./monitor.mdx).
