---
title: "Keep model context bounded"
description: "Keep evidence traceable and model requests within the serving window."
---

Use Membrane working memory and the SDK's `ContextSession` when a workflow gathers more evidence than fits in a single model request. Keep source artifacts so a later decision can verify the exact records it uses.

## Prepare a model turn

1. Save tool results and source evidence as immutable artifacts.
2. Declare the decision focus, required fields, and evidence references.
3. Select a bounded packet of supporting and opposing evidence. Check selected ranges against the saved source bytes.
4. Count the full request, including instructions, tool schemas, current input, and output allowance.
5. Dispatch when the request fits and retain the response receipt.

Use summaries to find evidence. Cite the verified source range in the final output. Runtime memory is run-scoped by default. Use explicit job scope only for authorized history shared across that job's runs.

## Budget the full request

```text
input_budget = window_tokens - output_reserve - safety_tokens
```

The SDK policy defaults to a 16,384-token window, 2,048 output tokens, and a 512-token safety reserve. Set the policy for your serving model and leave room for the complete request. The gateway can apply its own admission or output limit.

## Handle failures

| Signal | Next action |
| --- | --- |
| `NeedsPartition` | Divide the decision into smaller requests and carry verified results forward. |
| `AmbiguousInvocation` | Inspect the dispatch and receipt before choosing whether to use a new retry identity. |
| Source hash or range mismatch | Reject that evidence and check the source artifact. |
| Budget exhausted | Stop or return an explicit incomplete result. |
| Context service or model unavailable | Check runtime health and the blueprint's declared dependencies. |

A completed invocation can replay its saved result. An uncertain invocation may have reached the provider, so reconcile it before dispatching again.

## Diagnose and protect the context service

Use `mn runtime doctor` on the runtime host to inspect the context service. Use `mn blueprint doctor ./my-blueprint` from the package's parent directory to check declared requirements. Keep the service on a trusted network and scope access to the job, run, and principal. Keep private evidence out of progress messages and logs.

See [Author a blueprint](./blueprint-standard.mdx#extensions) for `mn.context` and [Configure and diagnose models](./model-runtime.mdx) for the serving route.
